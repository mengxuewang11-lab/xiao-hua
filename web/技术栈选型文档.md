# 用户 Web 技术栈选型文档

## 1. 定位

本目录后期存放面向创作者的正式网站，承担公开页面、账户入口、作品管理、完整设定维护、章节生成和长文本编辑。

## 2. 正式选型

```text
框架：Next.js（App Router）
语言：TypeScript
UI：Tailwind CSS + shadcn/ui
服务端状态：TanStack Query
当前实现：React useState/useEffect + fetch，业务扩大后再引入 TanStack Query
表单：React Hook Form + Zod
本地状态：Zustand（按需）
编辑器：Tiptap
动效：Motion（按需）
测试：Vitest + Testing Library + Playwright
组件管理：Storybook（组件规模扩大后）
监控：Sentry + Web Vitals（上线前）
包管理器：pnpm
```

## 3. 选择理由

- Next.js 同时适合公开页面和登录后的创作工作台。
- shadcn/ui 源码归项目所有，方便打造高质量定制界面。
- Tiptap 支持后续扩展批注、版本、局部重写和协作。
- TypeScript 与 OpenAPI 生成客户端配合，减少接口字段错误。
- Playwright 可覆盖从创建作品到保存章节的完整流程。

## 4. 服务端关系

```text
浏览器
→ Next.js
→ Spring Boot REST / SSE
→ MySQL / ModelProvider
```

Next.js 不直接访问 MySQL，不复制后端领域规则。当前按本地开发要求，模型 Key 可明文保存在后端本地配置或启动命令中，前端只传 `provider` 和 `model`。

前端请求约定：

```text
真实后端地址：http://localhost:8080/api/{控制器}/{接口名}
前端访问路径：/api/{控制器}/{接口名}
Next.js rewrite：/api/* → http://localhost:8080/api/*
```

示例：页面调用 `/api/chat/messages`，Next.js 转发到 `POST http://localhost:8080/api/chat/messages`。

## 5. 状态边界

- URL：页面位置、分页、筛选和可分享状态。
- TanStack Query：服务端数据与缓存。
- React Hook Form：表单状态。
- Tiptap：编辑器文档状态。
- Zustand：仅保存无法归入以上范围的客户端跨页面状态。

## 6. 暂缓能力

- 多人实时协作。
- WebSocket。
- 微前端。
- PWA 离线能力。
- 多套 UI 组件库混用。
