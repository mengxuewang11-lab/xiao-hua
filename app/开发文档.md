# App 开发文档

## 1. 初始化前提

需要先完成：

- Flutter Stable SDK。
- Android Studio。
- Android SDK、Platform Tools 和 Emulator。
- Flutter/Dart IDE 插件。
- `flutter doctor` 无阻塞错误。

Windows 可开发 Android；iOS 构建和发布最终需要 macOS 与 Xcode。

## 2. 目录约定

```text
app/
├── lib/
│   ├── app/                 # 应用入口、路由、主题
│   ├── core/                # 网络、错误、存储、通用工具
│   ├── design_system/       # Token 与通用组件
│   ├── features/
│   │   ├── auth/
│   │   ├── novels/
│   │   ├── settings/
│   │   └── chapters/
│   └── generated/           # 代码生成产物
├── assets/
├── test/
├── integration_test/
└── pubspec.yaml
```

按业务功能组织代码，不建立巨大的 `screens`、`models` 和 `services` 全局目录。

## 3. 状态与数据

- Riverpod 管理业务状态和依赖。
- Dio 统一访问 Spring Boot API。
- Freezed 定义不可变状态和 DTO。
- Token 只存放在安全存储。
- 服务端数据以 API 为准，本地只保存缓存与未提交草稿。
- 离线数据库启用前必须先设计同步和冲突策略。

## 4. 接口规范

- 普通查询和写入使用 REST。
- 生成过程使用 SSE 或任务状态轮询。
- 每个生成任务使用唯一 `taskId`。
- 写操作携带幂等键或数据版本号。
- 统一处理 `401`、`403`、`409`、`422`、`429` 和 `5xx`。
- App 切入后台后可通过任务查询接口恢复状态。

## 5. 设计系统

第一批基础组件：

```text
XhButton
XhTextField
XhDialog
XhToast
NovelCard
CharacterCard
ChapterCard
GenerationProgress
ReaderTheme
```

业务页面不得自行定义重复颜色、圆角和阴影。视觉 Token 集中在 `design_system`。

## 6. 测试重点

- Riverpod 状态与错误分支。
- 登录状态和 Token 刷新。
- 生成任务开始、恢复、完成和失败。
- 弱网下不会重复创建任务。
- 阅读主题与长文本渲染。
- Golden Test 覆盖核心组件和主要页面。
- 集成测试覆盖登录、作品列表和章节生成主链路。

## 7. 构建环境

```text
development
staging
production
```

客户端配置只包含公开 API 地址和构建标识。密钥、数据库密码和模型配置不得进入 App 包。

## 8. 开发顺序

1. 等后端 OpenAPI 基础契约稳定。
2. 初始化 Flutter 项目和设计系统。
3. 完成网络、鉴权和错误处理。
4. 完成作品列表与作品总览。
5. 接入章节阅读和生成状态。
6. 增加轻量编辑、缓存和通知。
