# App 技术栈选型文档

## 1. 定位

本目录后期存放 Android 与 iOS 客户端。App 面向创作者的移动场景，重点提供创意记录、作品查看、章节生成、沉浸阅读和轻量编辑。

## 2. 正式选型

```text
框架：Flutter
语言：Dart
设计基础：Material 3 + Cupertino
状态管理：Riverpod
路由：go_router
网络：Dio
数据模型：Freezed + json_serializable
安全存储：flutter_secure_storage
本地数据库：Drift（离线能力确定后引入）
组件预览：Widgetbook（设计系统成型后引入）
动效：Rive / Lottie（按设计需要引入）
测试：flutter_test + Golden Test + integration_test
监控：Sentry（上线前）
```

## 3. UI 策略

不依赖一套重型第三方 UI 模板。使用 Material 3 和 Cupertino 提供基础行为，通过自定义设计系统决定最终视觉：

- 颜色与渐变。
- 字体与排版层级。
- 间距、圆角和阴影。
- 按钮、输入框和弹窗。
- 作品卡、人物卡和章节卡。
- 阅读器主题。
- AI 生成进度与微动效。

## 4. 服务端关系

```text
Flutter App
→ HTTPS REST / SSE
→ Spring Boot
→ MySQL / ModelProvider
```

App 不直连 MySQL，不保存模型密钥，不直接调用任何模型厂商。

App 请求约定：

```text
真实后端地址：http://localhost:8080/api/{控制器}/{接口名}
客户端 baseURL：http://localhost:8080/api
业务代码路径：/{控制器}/{接口名}
```

示例：调用 `/novel-agent/runs`，最终请求为 `POST http://localhost:8080/api/novel-agent/runs`。Flutter 原生网络请求不受浏览器 CORS 限制。

## 5. 选择理由

- Android 与 iOS 高度一致的视觉表现。
- 对阅读器、动画和复杂布局控制力强。
- Material 3 与 Cupertino 组件完整。
- Riverpod 适合可测试、可组合的状态管理。
- Dio 便于统一鉴权、重试、取消和日志拦截。

## 6. 暂缓能力

- Drift：确认离线阅读或离线草稿后再引入。
- 推送通知：生成任务进入异步后台后再引入。
- Rive/Lottie：有正式动效稿后按需选择。
- 多人协作编辑：真实需求出现后再设计。
